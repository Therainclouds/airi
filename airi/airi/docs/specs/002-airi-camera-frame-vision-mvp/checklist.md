# 范围检查

- [x] 已明确本规格聚焦“摄像头抓取静态帧进入聊天视觉链路”
- [x] 已明确 MVP 不做原始视频流直接送模
- [x] 已明确 MVP 不做后台持续采集
- [x] 已明确 MVP 优先复用现有图片附件能力
- [ ] 已明确手动抓拍与低频自动抓帧的最终产品语义

# 架构检查

- [x] 已与 `001-airi-web-desktop-parity` 的 Shared Core / Runtime Adapters / Shell Apps 分层对齐
- [x] 已明确 camera-frame 以 `MediaCapability` 子契约方式落地
- [ ] 已明确 camera runtime adapter 的 owner 与注入方式
- [ ] 已明确共享摄像头会话 store / composable 的目录归属
- [ ] 已明确 Web 与 Desktop 的 adapter 差异边界

# 主链复用检查

- [x] 已明确抓拍结果复用现有图片附件数据结构
- [x] 已明确不新增 provider 视频协议
- [ ] 已明确聊天输入区摄像头入口与现有附件入口的组合方式
- [ ] 已明确抓拍附件在待发送区的展示、替换与移除规则
- [ ] 已明确发送后快照的清理策略

# 权限与隐私检查

- [x] 已明确默认关闭
- [x] 已明确必须由用户显式开启
- [x] 已明确界面需持续可见地显示预览或抓帧状态
- [ ] 已明确权限拒绝后的统一降级文案与恢复路径
- [ ] 已明确切路由、收起面板、发送完成后的资源释放策略

# 性能与资源检查

- [x] 已明确自动抓帧必须受严格节流限制
- [x] 已明确 MVP 默认最多保留 1 张最近快照
- [ ] 已明确抓帧频率上限与并发抓拍限制
- [ ] 已明确失败重试、设备占用与异常状态恢复规则
- [ ] 已建立媒体流释放与后台不运行的 smoke 检查

# 治理检查

- [x] 已明确不能直接把 MediaPipe devtools workshop 页面当成主链实现
- [x] 已明确后续多帧理解应建立在 camera-frame 能力之上扩展
- [ ] 已明确 capability 不可用时的 no-op / unsupported 语义
- [ ] 已明确 Desktop 后续扩展本地特有视频源时的壳层边界
- [ ] 已准备对应的分阶段实施任务与验收入口
