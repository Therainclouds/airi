# P0 语义冻结

- [ ] T001 盘点当前视觉主链、图片附件链路、vision 设置页与 MediaPipe workshop 的复用点
- [ ] T002 冻结 MVP 边界：只做前台显式授权、手动抓拍、低频自动抓帧，不做连续视频推理
- [ ] T003 在 `001-airi-web-desktop-parity` 的能力框架下冻结 `MediaCapability.cameraFrame` 子契约
- [ ] T004 定义统一状态机：`idle`、`requesting-permission`、`previewing`、`capturing`、`denied`、`error`
- [ ] T005 冻结隐私与资源策略：默认关闭、前台可见、用户可停止、路由切换时释放资源

# P1 运行时沉淀

- [ ] T006 抽出共享 camera runtime adapter，封装 `getUserMedia`、设备枚举、抓帧与流释放
- [ ] T007 为 `stage-web` 提供 Web camera adapter
- [ ] T008 为 `stage-tamagotchi` 提供与 Web 同语义的 renderer camera adapter
- [ ] T009 建立共享摄像头会话 store / composable，统一管理权限、状态、预览流与最近快照
- [ ] T010 建立抓帧节流策略，限制自动抓帧频率与并发抓拍
- [ ] T011 设计统一错误语义，收口权限拒绝、设备占用、无设备、抓帧失败等异常

# P1 主链接入

- [ ] T012 在 `packages/stage-pages` 的视觉设置页展示 camera-frame capability 的真实状态
- [ ] T013 在聊天输入区增加摄像头入口，不破坏现有附件与语音交互布局
- [ ] T014 建立摄像头预览面板，提供开始、停止、抓拍、自动抓帧开关与状态提示
- [ ] T015 将摄像头抓拍结果标准化为现有图片附件对象
- [ ] T016 复用 `ChatArea.vue` 的图片附件发送路径，确保无需新增 provider 视频协议
- [ ] T017 统一抓拍附件在待发送区的展示、替换与移除语义

# P2 自动抓帧 MVP

- [ ] T018 定义低频自动抓帧规则：默认关闭、仅前台预览期间有效、发送前只保留最近 1 张
- [ ] T019 建立自动抓帧与手动抓拍的冲突处理规则，避免重复附件和状态抖动
- [ ] T020 定义消息发送后快照清理策略：清空、保留最后一张或按配置替换
- [ ] T021 为自动抓帧补充性能观测：抓帧耗时、失败次数、被节流次数

# P2 治理与验证

- [ ] T022 补充 capability 不可用时的 no-op / 降级语义
- [ ] T023 建立摄像头会话生命周期 smoke：开启、抓拍、发送、关闭、切路由
- [ ] T024 建立资源释放检查，确保关闭面板或报错后媒体流已停止
- [ ] T025 建立权限回归检查，覆盖首次授权、拒绝后重试、系统撤销权限
- [ ] T026 盘点并避免从 devtools 页面直接复制业务实现到主链

# P3 后续扩展预留

- [ ] T027 为多帧理解预留扩展点，但保持主链消息协议继续以图片附件为核心
- [ ] T028 为视觉感知结果接入角色动作或环境状态预留独立扩展接口
- [ ] T029 明确 Desktop 后续如接入本地特有视频源时，不反向污染 Shared Core

# 验收标准

- [ ] A001 用户可以在主链中显式开启摄像头预览并手动抓拍
- [ ] A002 抓拍结果能以现有图片附件形式进入消息上下文
- [ ] A003 Web/Desktop 对权限、错误、关闭与降级行为呈现一致语义
- [ ] A004 关闭预览、切换页面或发生错误后，媒体流能被明确释放
- [ ] A005 自动抓帧不会在后台运行，也不会无限累积待发送附件
- [ ] A006 主链摄像头能力不再依赖 devtools 页面作为唯一入口
